# CSY Agent 安装步骤

[返回使用入口](../READ-ME.md) | [English](User-Guide-English.md)

## 安装要求

请先安装以下软件：

- **Windows 10/11（64 位）及浏览器**：[Windows 官方下载](https://www.microsoft.com/software-download/)。
- **DeepSeek Harness Web 版**：DSH **0.1.2-alpha.1**／Cordis **4.0.1**；[官方指定版本及安装说明](https://github.com/deepseek-ai/deepseek-harness/tree/dsh-v0.1.2-alpha.1)。
- **Node.js 24**：[官方下载](https://nodejs.org/en/download)，选择 Windows x64 的 24.x 版本，安装后应能在命令窗口中使用。
- **Python 3.12+**：[Windows 官方下载](https://www.python.org/downloads/windows/)。
- **PowerShell 7.x（64 位）**：[微软官方安装说明](https://learn.microsoft.com/en-us/powershell/scripting/install/install-powershell-on-windows)，选择 x64 稳定版。当前接入脚本要求此版本，可与 Windows 自带的 PowerShell 5.1 并存。

另外，准备一个支持原生 MCP 的 **BC On-Prem 测试环境**，以及用于连接的 BC 账号。

### 无法使用 PowerShell 7 时

接入脚本源码随程序提供：入口为程序根目录下的 `connect.cmd` 和 `Start-Harness.cmd`，主要接入逻辑位于 `integration/harness-integration/official-plugin/`。

如果无法使用 PowerShell 7，可以自行或借助自己的 AI Agent 修改相关脚本，尝试适配现有 PowerShell 版本。其他版本尚未验证，修改后需自行测试完整接入与启动流程；仅修改版本检查并不能保证兼容。

### 准备 BC HTTPS 证书与电脑信任

**需要什么：**使用当前 CSY 连接 BC MCP 时，BC 服务需提供有效的 HTTPS 服务器证书，运行 CSY 的电脑需信任该证书。证书中的主机名须与 MCP 地址匹配，且证书不能过期；本机测试也适用。

**它是什么：**这是用于验证 BC 服务器身份、建立加密连接的证书，由你自己的 BC 环境提供。CSY 不附带或自动配置这张证书。

**怎么准备：**使用 BcContainerHelper 创建 Docker 测试容器时，添加 `-useSSL` 启用 HTTPS，并添加 `-installCertificateOnHost` 将容器证书加入宿主机的 **Trusted Root Certification Authorities** 信任库，按提示批准管理员权限。若 CSY 运行在另一台电脑上，该电脑也需要配置证书信任。

- [微软 BcContainerHelper 参数与实现说明](https://github.com/microsoft/navcontainerhelper/blob/main/ContainerHandling/New-NavContainer.ps1)
- [微软 BC On-Prem 证书配置指南](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/deployment/implement-security-certificates-production-environment)

## 第一部分：配置 Gateway

### 1. 下载完整程序文件夹

获取提供者发布的完整 Windows x64 ZIP，将其中的 **DPBCMCP** 文件夹解压到本机可写的位置。GitHub 发布后，应下载 Release 附件中的程序 ZIP；自动生成的 Source code ZIP 不保证包含程序运行文件。

请保留文件夹内的全部文件，**不要只下载或单独移动 CSY.exe**。`_internal` 和 `integration` 必须与 `CSY.exe` 保持在同一目录。

### 2. 在 BC 中配置 MCP

1. 在 BC 中搜索并打开 **Model Context Protocol (MCP) Server Configurations**。
2. 选择 **New**，新建配置并填写名称。
3. 启用 **API Tools**，添加需要让 Agent 使用的 API 对象，并设置各对象允许的操作，例如读取、创建、修改、删除或执行动作。
4. 完成后启用 **Active**，再选择 **Set as Default**，将此配置设为默认。当前 Gateway 使用 BC 的默认 MCP 配置。

**MCP 中开放的 API 对象和操作，决定 Agent 可以使用哪些业务功能；连接账号本身也必须具有相应权限。** 例如，添加客户 API 页面并允许读取后，Agent 可通过对应工具查询客户；需要修改客户时，还须开放修改操作，并使用有相应权限的账号。这里添加的是 MCP 支持的 API 对象，并非任意 BC 页面或 Codeunit。

如果希望对象范围仅限手动添加的列表，请保持 **Discover Read-Only Objects** 关闭；启用后还可能发现未手动添加、但账号有权读取的 API 对象。

配置操作参考：[微软 MCP 配置文档](https://learn.microsoft.com/en-us/dynamics365/business-central/dev-itpro/ai/configure-mcp-server)。该文档以 Online 为适用范围，On-Prem 的具体界面和可用功能以安装版本为准。

### 3. 复制 BC MCP 地址

1. 打开刚才设为默认的 MCP 配置，选择 **Advanced → Connection String**。
2. 复制连接配置中 **url 的值**，不要复制整段 JSON。

这个地址就是下一步要填写到 Gateway 的 **BC MCP HTTPS URL**，正常情况下无需自己拼接地址或查找端口。

同时准备好目标 **BC 公司名称、用户名，以及密码或 Web Service Access Key**。

### 4. 打开 Gateway 并保存连接

1. 双击 DPBCMCP 文件夹中的 **CSY.exe**。浏览器会自动打开 Gateway 页面；使用期间保留程序窗口。
2. 页面上方的 **Service URL** 是本机 Gateway 地址，通常保持默认值。
3. 在连接表单中填写：

   | 页面字段 | 填写内容 |
   |---|---|
   | **BC MCP HTTPS URL** | 刚才从 Connection String 复制的 URL 值 |
   | **Company** | 要访问的 BC 公司名称，可在 BC 的公司选择页面查看 |
   | **User name** | BC 用户名 |
   | **Password or Web Service Access Key** | 该账号的密码或 Web Service Access Key |

4. 点击 **Save connection**。出现 `Connection saved locally.`，表示连接资料已保存。

至此完成 Gateway 配置，实际 BC 连接将在后续调用工具时验证。使用下面的自动接入流程时，无需手动生成或复制 Harness token。

## 第二部分：接入 DeepSeek Harness

### 首次接入 Harness

**已经安装 DeepSeek Harness？先打开 CSY.exe 并保存 BC 连接，再运行 connect.cmd。若未自动找到 Harness，请填写安装文件夹路径；程序会检查版本和必要文件，不符合时显示原因。**

1. 在**程序根目录**中打开 **connect.cmd**。
2. 输入 `yes` 并按 Enter，确认接入。
3. 程序先自动寻找 Harness。若提示 `Harness installation folder`，填写本机的 **Harness 安装文件夹**，例如 `D:\Apps\deepseek-harness`（仅为路径示例）。不要填写浏览器地址、快捷方式或登录资料。若另行询问 Python 或 PowerShell，则填写对应程序的完整路径。
4. 向导检查 DSH **0.1.2-alpha.1**、Cordis **4.0.1** 和必要文件。看到 **Setup complete** 表示设置完成；若显示 **Already configured**，已有接入配置，但连接尚未验证；可打开 **Start-Harness.cmd** 后执行只读查询。
5. 打开接入窗口显示的 Harness 地址，默认是 [http://127.0.0.1:3080](http://127.0.0.1:3080)。

#### 找不到或无法接入时

| 窗口提示／错误代码 | 含义和处理 |
|---|---|
| `HARNESS_NOT_FOUND` | 没有自动找到 Harness；按提示填写安装文件夹。 |
| `HARNESS_ROOT_INVALID` | 提供的目录无法识别为 Harness 安装；检查路径。 |
| `HARNESS_INSTALL_INCOMPLETE` | 找到了相关安装，但缺少必要文件或依赖；需要完整安装，源码目录还需完成构建。 |
| `HARNESS_VERSION_UNSUPPORTED` | 版本不符合要求；需要 DSH 0.1.2-alpha.1／Cordis 4.0.1。 |
| `PYTHON_NOT_FOUND`／`POWERSHELL_NOT_FOUND` | 未找到符合要求的运行环境；按提示提供 Python 3.12+ 或 64 位 PowerShell 7 的程序路径。 |

窗口可能先显示对应的英文说明；若最终失败，会显示错误代码。未识别的异常可能只有通用失败代码，此时保留窗口中的提示交给提供者检查。脚本不会自动安装、补齐或升级软件。

**提供路径不代表所有安装方式都兼容。** 本接入面向 Harness **Web 版**，桌面版尚未适配。源码构建或 npm 安装需要符合上述版本和目录要求；npx 可能使用缓存目录。各安装方式尚未逐一验收，以向导检查结果作为接入前提，不能把检查通过当作完整业务验证。

### CSY Agent 预设

**无需手动复制或移动预设文件。** 首次运行 `connect.cmd` 并完成设置后，脚本会自动创建 CSY Agent 预设并配置接入。

1. 等待接入窗口显示 **Setup complete**。**Already configured** 表示已有接入配置。
2. 打开窗口显示的 Harness 地址；若页面此前已打开，刷新页面。
3. 选择工作文件夹并新建会话，在 Agent／预设选择项中选择 **CSY Agent**，然后选择已配置的模型。

默认预设目录是 `%USERPROFILE%\.dsh\.agent-presets\bc-agent`。如果使用自定义 Harness 用户目录，预设位于该目录下的 `.agent-presets\bc-agent`。界面显示名为 **CSY Agent**，内部文件夹名仍为 `bc-agent`，无需改名。

如果列表没有 **CSY Agent**，先检查接入窗口是否报告设置失败，以及当前打开的是否为窗口显示的 Harness 地址。不要通过随意移动预设文件来处理。

### 配置模型

1. 在 Harness 中选择 **Settings** > **Models**。
2. 选择 Provider 旁的 **Edit**；未列出的 Provider 使用 **Add provider**。
3. 填写准备好的模型资料。
4. 选择 **Apply**。

### 开始聊天

1. 通过 **Choose workspace** 选定工作文件夹。
2. 选择 **New Session**。
3. 选择模型和 **CSY Agent**。
4. 发送下面的只读连接检查示例：

   > 请按可用工具及参数要求，只读查询一条已有销售订单，返回订单号、客户和状态。不要创建、修改、删除或过账。

## 下次使用

使用同一 Windows 用户和原文件夹。

1. 打开 **CSY.exe**。
2. 打开 **Start-Harness.cmd**，按提示提供安装路径。
3. 打开显示的 Harness 地址。

要停止 Gateway，在其窗口输入 `Q` 并按 Enter。

## 绑定失效或重新保存连接后

若工具提示 `The Gateway binding is no longer valid.`，可按以下步骤显式重绑：

1. 保持 `CSY.exe` 运行并确认已保存需要使用的 BC 连接。
2. 退出对应的 Harness 宿主程序；仅关闭浏览器标签页不会停止宿主程序。
3. 在本程序文件夹打开 **cmd**，运行：

   ```cmd
   call connect.cmd --refresh-binding && call Start-Harness.cmd
   ```

4. 输入 `yes`；成功后按任意键继续，打开显示的 Harness 地址，新建会话并选择 **CSY Agent**。
5. 重新执行上面的只读查询，确认返回真实 BC 结果。

脚本会自动寻找 PowerShell 7。若提示找不到，请填写本机实际安装的 `pwsh.exe` 完整路径；不要复制其他人的用户目录。

`Already configured` 只表示已有配置，**不代表绑定仍有效或 BC 已认证成功**。若仍收到 BC `403` 或 `BC_REJECTED`，保留错误代码，检查 BC 账号权限、MCP 配置和连接信息；不要把它直接当成另一个 Agent 占用。

## 地址与连接

默认 Gateway 地址：[http://127.0.0.1:8765](http://127.0.0.1:8765)。

首次启动需要指定其他空闲端口时，可使用 `CSY.exe --port <free-port>`，将 `<free-port>` 替换为实际端口号。保存的新地址在下次启动时生效。

不要使用其他 Gateway 实例已占用的端口或配置档案。保存连接不代表 BC 已认证成功。接入的 BC 工具具备修改业务数据的能力。

## 本地数据与分享

本地连接和设置保存在 `CSY.exe` 旁的 `data` 文件夹。Windows DPAPI 会将受保护的数据绑定到 Windows 用户和电脑。

分享时使用未保存个人资料的完整发布文件夹，不分享使用后的 `data` 文件夹。本副本以完整文件夹形式交付。

## 签名与验证状态

本程序未数字签名，Windows 可能显示未知发布者或安全提示。如果 Windows 阻止运行，请联系提供者。

程序不执行安装器部署、服务安装、防火墙修改、依赖升级或开机启动注册。全新电脑上的使用验证仍未完成。
